Problem 1：比較運算子

把 v == d 翻成 member function，並處理浮點數誤差。

需求先翻成可以檢查的規則

輸入

一個物件與 d

呼叫端是 MyVector 物件，參數是 double d。

檢查

逐一比較

所有 m[i] 都要與 d 足夠接近。

門檻

最多 0.00001

abs(m[i] - d) 不能大於門檻。

輸出

bool

只要一個元素超出門檻就回傳 false，全部通過才是 true。

關鍵：「全部成立」最直接的寫法，是遇到第一個失敗就提早回傳 false。

member operator 的左邊是呼叫物件

v == d
等同於
v.operator==(d)

左運算元 v

不會出現在參數列。函式裡用 this 或直接用 m、n 代表它。

右運算元 d

成為函式參數，因此宣告是 operator==(double d)。

尾端的 const：比較只讀取向量，不應改變物件，所以 member function 應標成 const。

浮點數比較使用差距，不直接用 ==

abs(m[i] - d) <= 0.00001

先相減

看兩個數值相隔多少。

›

取絕對值

不管誰比較大，差距都為正。

›

與門檻比較

差距在容許範圍內就視為相等。

例：
m[i] = 1.23000001
d = 1.23

差距是 0.00000001，小於門檻。
不要寫：m[i] == d
計算過程可能留下極小誤差。

Problem 1 解法：找到第一個不合格元素就停止

bool MyVector::operator==(double d) const
{
  for(int i = 0; i < n; i++)
  {
    if(abs(m[i] - d) > equalityGap)
      return false;
  }
  return true;
}
  • 1
    for 逐格讀取輸入是物件內的 n 個 double。
  • 2
    差距太大就 false後面的元素已不可能讓「全部相等」重新成立。
  • 3
    走完整圈才 true能走到最後，代表每一格都沒有觸發失敗條件。

Problem 2–3：索引運算子

同一個 v[i]，為什麼通常需要 const 與 non-const 兩個版本？

兩個版本的差別在「回傳後能不能修改」

// const 物件使用：只能讀
double operator[](int i) const;

// non-const 物件使用：可讀也可寫
double& operator[](int i);
回傳 double：把元素值複製出去。改回傳值不會改陣列。
回傳 double&：把原本元素的別名交出去，因此 v[i] = 9 可以直接寫回陣列。
函式尾端 const：承諾這次呼叫不修改物件可觀察到的狀態。

編譯器先看呼叫物件是不是 const

物件宣告運算式選到的版本能否放在 = 左邊
MyVector a(...);a[0]double& operator[](int)可以
const MyVector c(...);c[0]double operator[](int) const不可以
為什麼 non-const 物件不用 const 版本？兩個都能呼叫時，編譯器偏好不需要把物件視為 const 的 non-const 版本。

若移除 non-const 版本：讀得到，但寫不回去

MyVector a(...);

cout << a[0]; // 可以

a[0] = 9;
// 編譯失敗：左邊只是暫時的 double 值
  • 1
    non-const 物件可呼叫 const member「我承諾不改」對一般物件也成立。
  • 2
    但回傳型別是 double取得的是複製值，不是陣列元素本身。
  • 3
    因此失去寫入能力這不是找不到函式，而是回傳結果不能當可修改的左值。

若移除 const 版本：一般物件正常，const 物件不能索引

MyVector a(...);
a[0] = 9; // 可以

const MyVector c(...);
cout << c[0];
// 編譯失敗：const 物件不能呼叫
// non-const member function
問題：即使只是想讀取 const 向量，也沒有合法函式可呼叫。
連鎖影響：接收 const MyVector& 的函式也無法使用 [] 讀元素。
結論：兩個 overload 讓「一般物件可寫、const 物件唯讀」同時成立。

Problem 3：只留一個看似萬用的版本

double& MyVector::operator[](int i) const
{
  if(i < 0 || i >= n)
    exit(1);
  return m[i];
}

朋友的主張：

  • const 與 non-const 物件都能呼叫。
  • 回傳 reference，所以能放在 assignment 左邊。
先猜：這段會不會通過編譯？如果會，代價是什麼？

它會編譯，因為 const 限制的是指標本身

成員 double* m
在 const 函式內近似
double* const m

不能改指標位置

不能讓 m 改指向別的陣列。也就是指標本身受到 const 保護。

但 pointee 仍是 double

m[i] 指到的元素沒有自動變成 const，因此語法上可回傳 double&。

會編譯不代表設計正確：這個 reference 讓外部程式繞過 const 承諾。

實際結果：const 物件真的被改掉

const MyVector v(3, m);

cout << v[0] << "\n";
v[0] = 1;
cout << v[0] << "\n";
// 12_03_badConstMemberFunction.cpp

因果：operator[] 回傳原元素的 reference，assignment 透過這個別名寫入 heap 上的 double。
真正問題：呼叫者看到 const 會相信物件不可修改，但 API 卻偷偷交出可修改入口。

正確模式：const 版本回傳 const reference 或 value

// 一般物件：可寫
double& operator[](int i);

// const 物件：只讀
const double& operator[](int i) const;
教材原本版本：const overload 回傳 double，對小型基本型別很合理。
常見標準寫法：回傳 const double&，避免複製，同時禁止修改。
共同原則：const 物件取出的結果不能提供寫入原物件的能力。

運算式預期原因

a[0] = 5;可編譯回傳 double&，可寫回元素
cout << c[0];可編譯const 物件呼叫 const overload
c[0] = 5;不可編譯const overload 不交出可修改 reference

Problem 4：self-assignment

比較物件身分與比較物件內容，是兩個不同問題。

為什麼 assignment operator 先檢查地址？

const MyVector&
MyVector::operator=(const MyVector& v)
{
  if(this != &v)
  {
    // 必要時刪除舊陣列、配置新陣列
    // 再逐格複製 v.m[i]
  }
  return *this;
}

題目問：能不能換成 *this != v？

  • 會不會通過編譯？
  • 能不能避免 a1 = a1 的複製？
回答前先分清楚：this 是地址，*this 是物件。

地址比較回答「是不是同一個物件」

比較式比較的東西想回答的問題成本
this != &v兩個記憶體地址左右是否為同一個物件固定時間，O(1)
*this != v兩個物件的內容目前數值是否不同通常要走訪元素，O(n)
具體例子：a 與 b 是不同物件，但內容都等於 (1, 2, 3)。地址不同，值相等。

用值比較可能編譯，但做了不必要的工作

能否編譯

只有在類別已定義可用的 operator!= 時才可以。題目片段本身不足以保證這件事。

能否避開 a = a

若 operator!= 依內容比較，自己與自己內容相等，確實會跳過複製。

但它先比較了整個向量：為了省下一次 O(n) 複製，先做一次 O(n) 比較；地址比較只需要一次指標比較。
而且語意不同：兩個不同但內容相同的物件也會被當成「不用 assign」。結果目前相同，但這不是 self-assignment 檢查。

Problem 4 結論

1

編譯不一定

必須先有符合的 operator!=。

2

可跳過 a = a

值相等時條件為 false，因此不進複製區塊。

3

但比較較慢

值比較要逐格看，地址比較只看兩個指標。

4

應保留地址比較

this != &v 精確表達 self-assignment。

設計原則：用最直接的資訊回答問題。判斷物件身分就比較地址，不必先比較整份內容。

為什麼 self-assignment 可能危險？

// 若沒有 this != &v 保護
delete [] m;      // a = a 時，把自己的資料刪掉
m = new double[v.n];
m[i] = v.m[i];      // v 就是自己，來源資料早已被刪除
因果：左邊與右邊是同一個物件時，刪除 destination 的舊資料，也等於刪除 source 要提供的資料。
教材答案的實作：只有維度不同才 delete 與重新配置；self-check 仍讓意圖更清楚，也避免不必要的逐格複製。

這個 global function 不需要 friend

它實際做的事

friend 何時需要

只有非 member function 必須直接存取 private 成員時，才需要類別授權。

最小權限：能用 public interface 完成，就不要增加 friend。這讓 private 資料的入口更少。
實際驗證：答案檔把 friend 宣告註解掉，仍可編譯並輸出 Equal!。

Problem 7–8：stream operators

左運算元是 stream，所以要用 global function；回傳 stream reference 才能繼續串接。

cout << v 的左邊不是 MyVector

cout << v
呼叫

第一個參數：ostream&

接收現有的輸出串流。使用 reference，才不會複製 cout，也能保留串流狀態。

第二個參數：const MyVector&

輸出只讀向量，不應修改它；用 reference 避免複製整個物件。

operator<<：把格式寫進傳入的 stream

ostream& operator<<(ostream& out,
                            const MyVector& v)
{
  out << "(";
  for(int i = 0; i < v.n - 1; i++)
    out << v.m[i] << ", ";
  out << v.m[v.n - 1] << ")";
  return out;
}

為何不是 cout：寫入參數 out，同一份 operator 才能支援檔案串流等其他 ostream。

istream& operator>>(istream& in, MyVector& v)
{
  int tempN = 0;
  in >> tempN;
  if(tempN != v.n)
  {
    v.n = tempN;
    delete [] v.m;
    v.m = new double[tempN];
  }
  for(int i = 0; i < v.n; i++) in >> v.m[i];
  return in;
}

Problem 9：為何需要 operator overloading

泛型函式只看它使用了哪些語法。自訂類別若提供同樣操作，就能直接加入既有演算法。

template 不知道每個類別自訂的函式名稱

if(sorted[j] > sorted[j + 1])
{
  T temp = sorted[j];
  sorted[j] = sorted[j + 1];
  sorted[j + 1] = temp;
}
演算法作者只寫一次：他用標準語法 > 與 = 表達需求。
若每類名稱不同：有的叫 isGreaterThan，有的叫 larger，template 無法事先知道要呼叫哪個。

Bubble sort 每次比較相鄰兩格

for(int i = len - 1; i > 0; i--)
{
  for(int j = 0; j < i; j++)
  {
    if(sorted[j] > sorted[j + 1])
    {
      T temp = sorted[j];
      sorted[j] = sorted[j + 1];
      sorted[j + 1] = temp;
    }
  }
}
  • 1
    比較左右若左邊比較大，順序錯了。
  • 2
    用 temp 交換交換會用到 copy construction 與 assignment。
  • 3
    最大值逐輪往右每跑完一輪，右端至少多一個確定位置。

答案檔把「向量較大」定義為元素總和較大

bool MyVector::operator>(const MyVector& v) const
{
  int sum = 0, sumV = 0;
  for(int i = 0; i < n; i++) {
    sum += m[i];
    sumV += v.m[i];
  }
  return sum > sumV;
}
這是類別自行定義的順序：C++ 不知道向量誰大。operator> 把教材選定的「總和」規則提供給 bubble sort。
