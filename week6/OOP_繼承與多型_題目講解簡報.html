叫車平台：從 Entity 到 PassengerArray

先看題目：要模擬一個叫車平台

平台有已註冊的車與乘客。乘客提出叫車需求時，平台要找一輛空車給他。

車

共有 n 輛；每輛車可上線或離線。題目先忽略駕駛資料。

乘客

共有 m 位；乘客登入時提出叫車需求。

平台

把一輛空車指派給乘客，之後追蹤雙方狀態。

題目簡化：n、m 已知且固定，各在 1 到 10000 之間；上線車與乘客會記錄經緯度。

資料來源：原題 PDF 第 2–3 頁

這一頁先講完整應用情境。後面的程式練習只逐步建立資料類別與列印功能，尚未完成真正派車。

車與乘客各有三種狀態

是否上線Car（車）Passenger（乘客）
離線offline：車未接單offline：乘客不在服務中
上線、未開始服務empty：空車，可被指派waiting：已叫車並配對，正在等車
上線、服務中in-service：正在載客in-service：已上車，前往目的地
位置：題目只要求記錄上線車與上線乘客的經緯度；離線時列印不顯示座標。

資料來源：原題 PDF 第 2 頁

waiting 並非單純「尚未叫到車」；原題寫明已提出需求且已與車配對，正在等待車到。

一次叫車如何改變雙方狀態

以空車 5HE-313 和乘客 B90705023 為例，依原題描述走一次。

1

乘客登入叫車

平台要找一輛上線且 empty 的車。

2

完成指派

車變 in-service；乘客變 waiting。

3

車與乘客會合

乘客上車，變 in-service。

4

抵達目的地

車變 empty；乘客變 offline。

車也可以透過開啟或關閉 app，自行切換上線／離線。

→

→

題 4：建構與解構要成對

CarArray::CarArray() {
  cnt = 0;
  capacity = 20000;
  carPtr = new Car*[capacity];
}
CarArray::~CarArray() {
  for (int i = 0; i < cnt; ++i)
    delete carPtr[i];
  delete [] carPtr;
}
  • 1
    建構：配置指標位置，尚未建立 Car。
  • 2
    解構第一步：逐一刪除 cnt 個已建立的 Car。
  • 3
    解構第二步：用 delete [] 釋放指標陣列。

同名 print 不會自動依物件選擇

Entity* p = new Car("5HE-313",
  true, false, 0, 0);
p->print();  // Entity::print 非 virtual 時
             // 呼叫 Entity::print()
原因：p 的宣告型別是 Entity*；非 virtual 函式由這個型別決定呼叫哪一版。
題目想要：同一行 p->print()，依物件實際是 Car 或 Passenger 選各自的 print。

資料來源：原題 PDF 第 21 頁 · 課堂範例 14_icp06b_PassengerArrayBad.cpp

題 6：把 Entity::print 設為 virtual

class Entity {
public:
  virtual void print() = 0;
  virtual ~Entity() = default;
};
class Car : public Entity {
public:
  void print() override;
};
  • 1
    virtual：透過 Entity* 呼叫時，依實際物件型別選函式。
  • 2
    override：請編譯器確認 Car::print 真的覆寫父類別函式。
  • 3
    = 0：設成純虛擬函式，同時解決題 7。

資料來源：原題 PDF 第 21–22 頁 · 課堂範例 14_icp06d_PassengerArrayPureVirtual.cpp

原範例有 virtual print = 0，但沒有 virtual 解構函式；投影片加入建議修正。override 也是教學補充。

多型：同一呼叫，不同輸出

Entity* p宣告為父類別指標
→
實際物件Car 或 Passenger
→
p->print()呼叫實際物件版本

指向 Car

true, false → empty

指向 Passenger

true, false → waiting

資料來源：原題 PDF 第 21 頁

刪除 Entity* 需要 virtual 解構函式

Entity* p = new Car("5HE-313",
  true, false, 0, 0);
delete p;  // 透過 Entity* 刪除

class Entity {
public:
  virtual ~Entity() = default;
};
  • 1
    來源範例：EntityArray 對每個 Entity* 執行 delete。
  • 2
    問題：若 Entity 解構函式不是 virtual，透過父類別指標刪除子類別物件屬未定義行為。
  • 3
    修正：宣告 virtual 解構函式，確保刪除流程完整。

EntityArray::add 也可設為純虛擬

class EntityArray {
public:

class CarArray : public EntityArray {

三個容易混淆的地方

繼承欄位

Car 有 Entity 欄位，但建構時要呼叫 Entity(...)。

指標型別

Entity* 可存 Car 位址；實際建立的物件仍要是 Car。

virtual

用父類別指標呼叫 print 時，virtual 才會依實際物件選函式。
