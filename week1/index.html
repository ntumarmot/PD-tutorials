00 · Mental model

先建立一個畫面：變數有「值」也有「位址」

電腦的記憶體可以先想成很多有編號的小格子。宣告一個變數時，程式會找一塊空間放它；格子裡的內容是值，格子的編號就是位址（address）。

0x100其他資料
0x10410
0x108其他資料
重點：如果 int number = 10; 被放在位址 0x104，那麼 number 代表格子裡的值 10，而 &number 代表這個格子的位址。
01_address.cpp
#include <iostream>
using namespace std;

int main() {
    int number = 10;

    cout << "值：" << number << '\n';
    cout << "位址：" << &number << '\n';

    return 0;
}

位址每次執行可能不同，這是正常的。現在只要確認：第一行會印出 10，第二行會印出一個像 0x... 的位址。

01 · Pointer basics

指標是什麼？

指標（pointer）也是一種變數，但它存的不是一般整數，而是另一個物件的記憶體位址。透過這個位址，我們就能找到原本的物件。

02_pointer.cpp
#include <iostream>
using namespace std;

int main() {
    int number = 10;
    int* pointer = &number;

    cout << number << '\n';   // 10
    cout << pointer << '\n';  // number 的位址

    return 0;
}
  1. int number = 10; 建立一個整數，裡面放 10。
  2. &number 取得 number 的位址。
  3. int* pointer 宣告一個「指向 int 的指標」。
  4. pointer = &number 把 number 的位址存進指標。
* 會依出現位置表示不同事情 在宣告裡，int* pointer 的 * 表示「pointer 是指標」；在運算式裡，*pointer 表示「走到 pointer 存的位址，取出那裡的值」。

沒有要指向任何東西時：使用 nullptr

03_nullptr.cpp
#include <iostream>
using namespace std;

int main() {
    int* pointer = nullptr;

    if (pointer == nullptr) {
        cout << "目前沒有指向任何 int\n";
    }

    return 0;
}

nullptr 明確表示「沒有有效位址」。在它指向有效物件之前，不可以寫 *pointer。

02 · Dereference

用指標讀取、修改原本的值

對指標使用 * 叫做解參考（dereference）：根據指標裡的位址，找到那個位址中的物件。這讓函式有機會修改外部原本的變數。

04_dereference.cpp
#include <iostream>
using namespace std;

int main() {
    int number = 10;
    int* pointer = &number;

    cout << *pointer << '\n'; // 讀取：印出 10
    *pointer = 25;               // 修改 number
    cout << number << '\n';  // 印出 25

    return 0;
}
因果關係：pointer 裡存著 number 的位址，所以 *pointer = 25 修改的就是那個位址中的值。結果不是只改到指標，而是 number 本身變成 25。

把修改動作放進函式

05_add_one.cpp
#include <iostream>
using namespace std;

void addOne(int* value) {
    *value = *value + 1;
}

int main() {
    int score = 80;
    addOne(&score);
    cout << score << '\n'; // 81
    return 0;
}

main 傳入 &score，也就是 score 的位址。addOne 收到位址後，用 *value 找到並修改原本的 score。

03 · Swap with pointers

為什麼原本的 swap 沒有效？

一般參數預設採用傳值（pass by value）：函式收到的是值的複本。交換複本不會改到 main 裡的原始變數。

06_broken_swap.cpp
#include <iostream>
using namespace std;

void swapWrong(int a, int b) {
    int temp = a;
    a = b;
    b = temp;
}

int main() {
    int x = 3, y = 8;
    swapWrong(x, y);
    cout << x << ' ' << y << '\n'; // 仍是 3 8
}

呼叫時，x 的值被複製給 a，y 的值被複製給 b。函式結束後，區域變數 a、b 被移除，因此外面的 x、y 沒有改變。

修法一：傳入兩個變數的位址

07_pointer_swap.cpp
#include <iostream>
using namespace std;

void swapByPointer(int* a, int* b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

int main() {
    int x = 3, y = 8;
    swapByPointer(&x, &y);
    cout << x << ' ' << y << '\n'; // 8 3
    return 0;
}
  1. &x 與 &y 把兩個原始變數的位址傳給函式。
  2. *a 代表原本的 x；*b 代表原本的 y。
  3. temp 暫存原本的 x，避免第一個指定動作把它蓋掉。
  4. 兩次指定都直接寫入原始位址，所以回到 main 後結果仍然保留。

04 · References

修法二：使用參考

參考（reference）可以把參數當成外部變數的別名。函式裡寫 a，實際上就是在使用呼叫端傳入的那個變數，不需要再寫 *a。

08_reference_swap.cpp
#include <iostream>
using namespace std;

void swapByReference(int& a, int& b) {
    int temp = a;
    a = b;
    b = temp;
}

int main() {
    int x = 3, y = 8;
    swapByReference(x, y);
    cout << x << ' ' << y << '\n'; // 8 3
    return 0;
}
注意同一個符號的不同位置：在 int& a 中，& 是型別的一部分，表示 a 是參考；在 &x 中，& 是取址運算子，表示取得 x 的位址。
比較指標參數參考參數
函式宣告void f(int* p)void f(int& r)
呼叫方式f(&x)f(x)
函式內取值*pr
能否表示「沒有指向物件」可以設成 nullptr一般參考必須綁定有效物件
適合情況允許「可能沒有物件」，或需要操作位址參數一定存在，而且希望語法簡潔

實務提醒如果只是想讓函式修改一個一定存在的參數，通常參考比較容易讀；如果「沒有物件」也是合法狀態，指標的 nullptr 才能明確表示它。

05 · Dynamic memory

new / delete：執行時才要求一塊空間

new 會在程式執行期間配置（allocate）記憶體，並回傳那塊空間的位址。因為回傳的是位址，所以需要用指標接住。使用完畢後，要用相對應的 delete 釋放空間。

09_new_delete.cpp
#include <iostream>
using namespace std;

int main() {
    int* score = new int{90};

    cout << *score << '\n'; // 90
    *score = 100;
    cout << *score << '\n'; // 100

    delete score;
    score = nullptr;
    return 0;
}
  1. new int{90} 配置一個能放 int 的空間，初始值是 90。
  2. new 回傳該空間的位址，score 把位址存起來。
  3. *score 讀寫那塊空間中的整數。
  4. delete score 把不再需要的空間還回去。
  5. score = nullptr 避免指標繼續保留已失效的舊位址。

動態陣列：new[] 要配 delete[]

10_dynamic_array.cpp
#include <iostream>
using namespace std;

int main() {
    int size;
    cin >> size;

    int* scores = new int[size]{};
    for (int i = 0; i < size; ++i) {
        scores[i] = (i + 1) * 10;
    }

    for (int i = 0; i < size; ++i) {
        cout << scores[i] << ' ';
    }

    delete[] scores;
    scores = nullptr;
    return 0;
}
配對規則一定要一致 單一物件：new 配 delete。陣列：new[] 配 delete[]。兩組不能混用。

知道語法，也要知道現代做法學習 raw pointer（原始指標）能幫助理解記憶體；但在一般 C++ 程式中，動態陣列通常優先使用 std::vector，資源擁有權則常交給 smart pointer（智慧指標），可減少忘記釋放的風險。

06 · Common mistakes

四個最常見的錯誤

指標錯誤常常不是編譯失敗，而是程式執行時才出問題。先學會辨認危險寫法，比背更多語法重要。

1. 未初始化指標int* p; 裡面是未知位址。若還沒有目標，寫成 int* p = nullptr;。
2. 解參考 nullptr*p 前要確定 p != nullptr，否則沒有有效物件可讀寫。
3. delete 後繼續使用delete p 後原空間已失效；這時再使用 *p 是未定義行為。
4. 忘記 delete配置的空間失去所有可用指標後就無法釋放，造成 memory leak（記憶體洩漏）。
11_safe_pattern.cpp
#include <iostream>
using namespace std;

int main() {
    int* number = new int{42};

    if (number != nullptr) {
        cout << *number << '\n';
    }

    delete number;
    number = nullptr;
    return 0;
}

不要把 nullptr 檢查誤解成萬能保護指標也可能不是 nullptr，卻仍指向已被釋放的空間。真正重要的是清楚知道：誰建立資源、誰負責釋放、釋放後就不再使用。

Problem 1

觀察記憶體位址與配置空間

原題希望觀察變數位址，以及迴圈中配置了多少記憶體。原始解答可以編譯，但它只印出指標變數本身的位址，沒有印出 new 回傳的 heap 位址，而且沒有釋放每次配置的陣列。

08_01_see_sol.cpp｜教學修正版
#include <iostream>
using namespace std;

int main() {
    int anInteger = 0;
    cout << "anInteger 的位址：" << &anInteger << '\n';

    for (int i = 0; i < 10; ++i) {
        int* anotherInteger = new int[100];

        cout << "i 的位址：" << &i << '\n';
        cout << "指標變數的位址：" << &anotherInteger << '\n';
        cout << "heap 陣列的起始位址：" << anotherInteger << '\n';

        delete[] anotherInteger;
    }
    return 0;
}
&anotherInteger

取得「指標變數本身」的位址。這個變數通常位於函式的 stack frame，而且每圈可能重用同一位置。

anotherInteger

指標裡存的值，也就是 new int[100] 配置之 heap 區塊的起始位址。

配置量怎麼算？每圈配置 100 × sizeof(int) bytes，共 10 圈，因此總配置量是 1000 × sizeof(int) bytes。若這台電腦的 sizeof(int) == 4，就是 4000 bytes；C++ 標準本身不保證 int 一定是 4 bytes。

原始解答的風險原檔每圈都 new int[100]，卻沒有 delete[]，因此會造成 memory leak。上面的教學版已補上釋放。

Problem 3

把兩個指標傳進函式，回傳較大值的位址

maxPtr 收到的是 a、b 的位址。它先用 *a、*b 比較兩個值，再回傳其中一個原始位址。

08_03_passPointer_sol.cpp
#include <iostream>
using namespace std;

int* maxPtr(int* a, int* b) {
    if (*a > *b)
        return a;
    return b;
}

int main() {
    int a = 0, b = 0;
    cin >> a >> b;
    cout << *maxPtr(&a, &b) << '\n';
    return 0;
}

小例子：輸入 8 13&a、&b 傳入函式 → *a > *b 是 8 > 13，結果為 false → 回傳 b 的位址 → 呼叫端用最外層的 * 取得該位址中的值 → 輸出 13。

為什麼回傳這個指標是安全的？函式回傳的是 main 中變數 a 或 b 的位址。當 maxPtr 結束時，main 還沒結束，所以這兩個物件仍然存在。

Problem 4

不能回傳區域變數的位址

原程式在 maxAddr 裡建立區域變數 c，然後回傳 &c。函式結束後 c 的生命週期已結束，回傳的指標變成 dangling pointer（懸空指標）。

原本的危險寫法
int* maxAddr(int a, int b) {
    int c = a;
    if (b > a)
        c = b;
    return &c;
}

直接後果呼叫端執行 *maxLoc 是 undefined behavior。程式可能碰巧印出正確數字、印出垃圾值或直接崩潰；「某次執行看起來正常」不能證明它正確。

08_04_returnPointer_solWithModification.cpp｜安全修法
#include <iostream>
using namespace std;

int* maxPtr(int* a, int* b) {
    if (*a > *b)
        return a;
    return b;
}

int main() {
    int a = 0, b = 0;
    cin >> a >> b;

    int* maxAddr = maxPtr(&a, &b);
    cout << *maxAddr << '\n';
    return 0;
}

Problem 5

回傳 heap 位址後，呼叫端負責 delete

這題改用 new int 建立動態物件。函式結束後，heap 物件不會像區域變數一樣自動消失，因此回傳它的位址可以繼續使用；代價是必須明確決定誰負責釋放。

08_05_DMA_sol.cpp｜修正原檔 typo
#include <iostream>
using namespace std;

int* maxAddr(int a, int b) {
    int* cPtr = new int(a);
    if (b > a)
        *cPtr = b;
    return cPtr;
}

int main() {
    int a = 0, b = 0;
    cin >> a >> b;

    int* maxLoc = maxAddr(a, b);
    cout << *maxLoc << '\n';

    delete maxLoc;
    maxLoc = nullptr;
    return 0;
}
函式做什麼？

new int(a) 建立一個 heap 上的整數並以 a 初始化；若 b 較大，就把該整數改成 b。

呼叫端做什麼？

maxLoc 接住位址、讀取結果，最後用 delete maxLoc 釋放同一個物件。

原始檔有一個確定的編譯錯誤原始第 21 行寫成 delete maxAddr;，但 maxAddr 是函式名稱，不能 delete。正確目標是指標變數 maxLoc。上方程式已修正。

更簡單的設計這個函式若只需要回傳最大值，直接回傳 int 比配置動態記憶體更簡單。這題使用 new 的主要目的，是練習動態物件的生命週期與釋放責任。

Problem 6

大型區域陣列與動態陣列

兩支程式都嘗試建立 100,000,000 個 int。若 sizeof(int) == 4，大約需要 400 MB。差別在於儲存空間與失敗方式。

stack_array.cpp
#include <iostream>
using namespace std;

int main() {
    cout << 123;
    int array[100000000];
    cout << 456;
    return 0;
}
heap_array.cpp｜補上釋放
#include <iostream>
using namespace std;

int main() {
    cout << 123;
    int* array = new int[100000000];
    cout << 456;

    delete[] array;
    return 0;
}
比較大型區域陣列new[] 動態陣列
儲存區域通常使用 stack使用 dynamic storage，實作上通常稱 heap
常見結果可能因 stack 空間不足而失敗可能成功；空間不足時 new 通常丟出 std::bad_alloc
釋放方式離開作用域自動結束生命週期使用完必須 delete[]

執行結果不是每台電腦都相同stack 限制、可用記憶體、編譯器最佳化都會影響結果。另外第一個 cout << 123 沒有換行或手動 flush；若程式隨後異常終止，畫面上不一定來得及看到 123。

Problem 7

Adjacency list 轉 adjacency matrix

這題把每個節點的鄰居清單讀進 int** neighbors，再輸出 n × n 的矩陣。對節點 i 而言，若 j 出現在 neighbors[i]，矩陣的 matrix[i][j] 就是 1。

讀入 adjacency list 的核心結構
int nodeCnt = 0;
cin >> nodeCnt;

int** neighbors = new int*[nodeCnt];
int* degrees = new int[nodeCnt];

for (int i = 0; i < nodeCnt; ++i) {
    cin >> degrees[i];
    neighbors[i] = new int[degrees[i]];

    for (int j = 0; j < degrees[i]; ++j)
        cin >> neighbors[i][j];
}
neighbors 的角色

它指向一個「指標陣列」。第 i 格是 int*，再指向節點 i 的鄰居陣列。

degrees 的角色

degrees[i] 告訴程式第 i 個鄰居陣列有幾格，避免讀取超出範圍。

慢速解法：每個矩陣位置都回頭搜尋清單

slow solution｜核心三層迴圈
for (int i = 0; i < nodeCnt; ++i) {
    for (int j = 0; j < nodeCnt; ++j) {
        bool isNeighbor = false;

        for (int k = 0; k < degrees[i]; ++k) {
            if (neighbors[i][k] == j) {
                isNeighbor = true;
                break;
            }
        }

        cout << (isNeighbor ? 1 : 0);
    }
}

這個版本對每個 (i, j) 都搜尋一次節點 i 的鄰居清單。若圖有 m 條無向邊，總搜尋量可寫成 O(nm)，稠密圖最壞可到 O(n³)。有函式版只是把搜尋動作包進 isNeighbor()，複雜度不會因此改變。

快速解法：先建立矩陣，再直接填 1

08_07_adjacencyList_fastSol.cpp｜核心步驟
int** matrix = new int*[nodeCnt];

for (int i = 0; i < nodeCnt; ++i) {
    matrix[i] = new int[nodeCnt];
    for (int j = 0; j < nodeCnt; ++j)
        matrix[i][j] = 0;
}

for (int i = 0; i < nodeCnt; ++i) {
    for (int j = 0; j < degrees[i]; ++j) {
        int neighborID = neighbors[i][j];
        matrix[i][neighborID] = 1;
    }
}

for (int i = 0; i < nodeCnt; ++i) {
    for (int j = 0; j < nodeCnt; ++j) {
        if (j > 0)
            cout << ' ';
        cout << matrix[i][j];
    }
    cout << '\n';
}

for (int i = 0; i < nodeCnt; ++i)
    delete[] matrix[i];
delete[] matrix;
  1. 配置 n 列，每列再配置 n 個 int，並把矩陣全部設成 0。
  2. 只走訪 adjacency list 中實際存在的鄰居，把對應的 matrix[i][neighborID] 設成 1。
  3. 逐列輸出矩陣；最後先釋放每一列，再釋放最外層的指標陣列。

複雜度初始化與輸出矩陣各需要 O(n²)；填入鄰接關係需要 O(m)。總時間是 O(n² + m)，對 simple graph 可簡化為 O(n²)。代價是另外使用 O(n²) 的矩陣空間。

慢速版（無函式） 慢速版（有函式） 快速版

釋放順序不能反過來若先 delete[] neighbors，就失去每一列 neighbors[i] 的位址，後面無法逐列釋放。正確順序是先刪內層陣列，再刪外層指標陣列，最後刪 degrees。

課後練習

建議先在紙上預測答案，再貼到編譯器執行。若答案不同，從每個指標目前存的位址開始追。

練習 1：執行後 x 是多少？

先不要執行程式，請追蹤每一行後 x 的值，並寫下最後答案。

practice_1.cpp
int x = 5;
int* p = &x;
*p = *p + 3;
查看參考答案

答案：x 是 8。p 指向 x，所以 *p 就是原本的 x。

練習 2：完成 doubleValue

請在空白處補上一行，讓函式能把外面的 number 乘以 2。

practice_2.cpp
void doubleValue(int* value) {
    // 請完成這一行
}

int main() {
    int number = 7;
    doubleValue(&number);
    // number 應該變成 14
}
查看參考答案

參考答案：*value = *value * 2;。左邊表示要修改指向的物件，右邊先讀出原值再乘以 2。

練習 3：找出動態陣列的錯誤

下面的程式可以編譯，但記憶體釋放方式不正確。請指出錯誤並改寫最後一行。

practice_3.cpp
int* data = new int[5];
data[0] = 10;
delete data;
查看參考答案

錯在最後一行。因為前面使用 new int[5] 建立陣列，釋放時必須使用 delete[] data;。

離開教室前，確認自己能回答

&x 得到什麼？變數 x 的記憶體位址。
*p 得到什麼？p 指向的物件；可以讀取，也可以修改。
swap 為何要指標或參考？因為必須改到呼叫端的原始變數，而不是只交換複本。
new 之後要記得什麼？清楚保留位址、用完正確 delete，之後不再使用舊位址。
