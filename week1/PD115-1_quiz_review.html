Question 01

第一題｜判斷題

25 分，每題 5 分

這一題的關鍵不是背答案，而是找出句子裡的絕對用語、運算順序與記憶體前提。先選 T 或 F，再展開講解。

a

在 C++ 中，如果把兩個很大的整數相乘，再把結果存入一個整數變數，可能會發生溢位（overflow）。

先想：數學上的乘積如果超過型別能表示的範圍，電腦還能完整存下來嗎？

展開講解與答案
官方答案：T
白話解釋

int 能表示的數值範圍有限。兩個操作數本身都放得進 int，不代表它們的乘積也放得進去。

小例子

假設某型別最大只能放 100，那麼 20 × 20 = 400 就超出範圍。

考場一句話T。整數乘積可能超過目標整數型別可表示的範圍。

嚴謹補充：在標準 C++ 中，有號整數溢位屬於 undefined behavior（未定義行為）；無號整數則依模數規則回繞。本題官方答案是 T。

b

若 a = 1、b = 23、c = 8、d = 18，則 a > b && c > d 在回傳結果前會進行兩次比較與一次「and」運算。

先想：&& 左邊已經是 false 時，右邊還需要算嗎？

展開講解與答案
官方答案：F
  1. 先算 a > b，也就是 1 > 23，結果為 false。
  2. false && 任何值 都一定是 false，因此結果已經確定。
  3. C++ 使用 short-circuit evaluation（短路求值），不再計算 c > d。

考場一句話F。第一個比較已為 false，&& 短路，因此第二個比較不會執行。

c

從定義它的那一行開始，一個全域變數（global variable）可在定義它的整個程式中被存取。

先想：全域變數的 scope（作用域）從哪裡開始？局部變數會不會暫時遮住同名的全域變數？

展開講解與答案
官方答案：T

在這份考卷的基礎、單一原始檔語境中，全域變數從宣告點開始，到該原始檔結束都在作用域內。後面定義的函式可以使用它。

global_scope.cpp
#include <iostream>
using namespace std;

int score = 10;

void showScore() {
    cout << score << '\n';
}

考場一句話T。全域變數從宣告位置起，到檔案後續範圍皆可見。

嚴謹補充：這不代表任何地方都一定能直接寫同一個名稱。同名局部變數可能遮蔽它；跨多個原始檔時也涉及 linkage（連結性）與 extern。這些細節不是本題主要考點。

d

給定長度為 10 的靜態配置整數陣列 arr，cout << arr + 2; 會印出索引值為 2 的陣列元素位址。

先想：在運算式中，arr 通常會轉成哪一個元素的位址？位址加 2 又會往後移幾個元素？

展開講解與答案
官方答案：T
  1. 在這個運算式中，arr 會轉成指向第一個元素的指標，也就是 &arr[0]。
  2. arr + 2 不是增加 2 bytes，而是往後移動兩個 int 元素。
  3. 因此 arr + 2 等同於 &arr[2]，輸出的是該位址，不是元素值。

考場一句話T。arr + 2 等同於 &arr[2]。

e

執行 char a[1000]; cin >> a; 並輸入 800 個字元，原則上沒問題；若執行 char* b; cin >> b; 並輸入 800 個字元，則有機率發生 run-time error。

先想：a 已經有實際陣列空間；只有宣告 char* b 時，有沒有替 800 個字元準備空間？

展開講解與答案
官方答案：T
char a[1000]

已配置 1000 個 char 的空間。800 個字元再加結尾的 '\0'，共 801 格，放得下。

char* b

只建立一個未初始化的指標，沒有建立可寫入 800 個字元的陣列。把輸入寫到未知位址會造成 undefined behavior。

考場一句話T。a 有足夠陣列空間；b 沒有指向已配置的有效緩衝區。

版本補充：這個答案依本課程常見的 C++17 輸入語境說明。實務上仍不建議用沒有長度限制的字元陣列輸入；使用 std::string 會更安全。

Question 02

第二題｜簡答題

30 分，每小題 15 分；每題限 100 字

簡答題要先直接回答「什麼時候／是否正確」，再補一個原因。不要先繞一大圈才出現結論。

a

什麼時候在往函式傳入陣列時，應該將其加上 const 並宣告為常數陣列？

先想：這個函式是要修改陣列，還是只讀取陣列內容？

展開講解與參考作答
官方答案核心：只讀不改

當函式只需要讀取陣列元素、不應修改呼叫端的陣列內容時，參數應加上 const。編譯器會阻止函式內對元素賦值，也能讓函式接收本來就是常數的陣列。

const_array.cpp
int sum(const int values[], int size) {
    int total = 0;
    for (int i = 0; i < size; ++i) {
        total += values[i];
    }
    return total;
}

100 字內參考答案當函式只需讀取陣列、不應修改其元素時，應將參數宣告為 const 陣列，以防止誤改呼叫端資料，並可接收常數陣列。

官方評分重點：10 分

必須寫出使用時機：函式只讀取、不應修改陣列元素。

官方評分重點：5 分

必須寫出目的：限制修改、保護呼叫端原始資料或避免誤改。

b

如果有人說 call by reference 的函式都可以用 call by pointer 改寫，正確嗎？為什麼？

先想：參考讓函式直接操作原物件；指標能不能藉由「位址＋解參考」找到同一個原物件？

展開講解與參考作答
官方答案：正確
reference_vs_pointer.cpp
void addOneByReference(int& value) {
    value++;
}

void addOneByPointer(int* value) {
    (*value)++;
}

int main() {
    int number = 5;
    addOneByReference(number);
    addOneByPointer(&number);
    return 0;
}
  1. 參考版本中的 value 是 number 的別名。
  2. 指標版本收到 &number，也就是 number 的位址。
  3. 指標版本使用 *value 找回原本的 number，因此也能修改它。

100 字內參考答案正確。reference 是原變數的別名；pointer 可保存原變數位址，呼叫時傳入位址並在函式內 dereference，即可操作同一變數。

先給結論：3 分

明確回答「正確」。

reference：4 分

說明 reference 是原變數的別名，或能操作原變數。

pointer：4 分

說明 pointer 可接收、保存原變數的位址。

dereference：4 分

說明解參考後可操作同一變數，因此能達到相同效果。

嚴謹補充：兩者功能相近，但語意不完全一樣。一般參考必須綁定有效物件；指標可以是 nullptr，也可改指向別處。const reference 還能直接綁定暫時物件，所以不能把「可改寫」理解成所有呼叫形式都完全相同。

Question 03

第三題｜兩步內可抵達的節點

20 分

輸入是一個 n × n 相鄰矩陣 A 與起點 v。要計算零步、一步、兩步能到達的不同節點數量，且同一節點只能算一次。

題目真正要求的三件事

  1. 零步：起點 v 本身一定要算。
  2. 一步：找出所有滿足 A[v][i] = 1 的節點 i。
  3. 兩步：從每個一步鄰居 i 再找所有滿足 A[i][j] = 1 的節點 j。

最容易漏掉的地方：同一節點可能有多條路徑抵達，所以不能每找到一次就直接把答案加一。需要一個布林陣列記錄「這個節點是否已經算過」。

1 → 2 1 → 3 1 → 2 → 4 1 → 3 → 4

上例從 1 出發，節點 4 雖然能透過兩條路徑抵達，仍只能計算一次。最後算到的是 {1, 2, 3, 4}，答案為 4。

展開虛擬碼、正確性與複雜度

虛擬碼

count-within-two-steps.pseudocode
COUNT-WITHIN-TWO-STEPS(A, n, v)
    建立 reachable[1..n]，全部設為 false
    reachable[v] = true

    for i = 1 to n
        if A[v][i] == 1
            reachable[i] = true

            for j = 1 to n
                if A[i][j] == 1
                    reachable[j] = true

    count = 0
    for i = 1 to n
        if reachable[i] == true
            count = count + 1

    return count

為什麼它是對的？

不會漏算

reachable[v] 處理零步；第一層找到所有一步鄰居；第二層從每個一步鄰居出發，找到所有兩步節點。

不會重複算

不論某個節點被找到幾次，都只是把同一格 reachable[j] 設成 true。最後每一格只檢查一次。

時間複雜度怎麼算？

部分最多做幾次成本
初始化 reachablen 格O(n)
掃描起點的一步鄰居n 個候選O(n)
掃描每個一步鄰居的整列最多 n 列，每列 n 格O(n²)
計算 true 的數量n 格O(n)

官方複雜度推導若 d(v) 是起點 v 的 degree，總時間為 T(n) = O(n + d(v)n)。因為 d(v) ≤ n - 1，最壞情況是 O(n²)。額外空間為 O(n)。

官方評分檢查

可達性紀錄
正確初始化並使用 reachable，且把起點 v 納入。
一步與兩步
能正確找出一步、兩步內可達的節點。
去除重複
同一節點即使由多條路徑抵達，也只計算一次。
結果與複雜度
正確回傳總數，並依實際演算法分析時間複雜度。

對應的 C++ 寫法

two_steps.cpp
#include <vector>
using namespace std;

int countWithinTwoSteps(const vector<vector<int>>& A, int v) {
    int n = A.size();
    vector<bool> reachable(n, false);
    reachable[v] = true;

    for (int i = 0; i < n; ++i) {
        if (A[v][i] == 1) {
            reachable[i] = true;

            for (int j = 0; j < n; ++j) {
                if (A[i][j] == 1) {
                    reachable[j] = true;
                }
            }
        }
    }

    int count = 0;
    for (bool canReach : reachable) {
        if (canReach) {
            ++count;
        }
    }
    return count;
}

編號差異：題目節點編號是 1 到 n；上面的 C++ 使用 vector，所以索引改成 0 到 n - 1。若題目傳入的 v 仍是 1-based，要先做 --v。

Question 04

第四題｜追蹤程式輸出

25 分，每小題 5 分

不要直接在腦中跑完整支程式。把它切成三塊：while 迴圈、函式參數、全域與區域變數。

quiz_question_4.cpp
#include <iostream>
using namespace std;

int g = 18;

int f(int x, int v[]) {
    x = 10;
    *(v + 2) = 100;
    int g = 123;
    return x;
}

int main() {
    int start = 13;
    int loopCount = 0;
    while (start > 6) {
        if (start % 2 == 0)
            start /= 2;
        else
            start = 3 * start + 1;
        loopCount++;
    }
    cout << loopCount << "\n"; // (a)
    cout << start << "\n";     // (b)

    int aValue = 0;
    int values[10] = {0};
    f(aValue, values);
    cout << aValue << "\n";    // (c)
    cout << values[2] << "\n"; // (d)

    cout << g << "\n";         // (e)
    return 0;
}
展開逐行追蹤與答案

第一塊：while 迴圈決定 (a)、(b)

第幾圈進入時 start判斷更新後 startloopCount
113奇數，算 3 × 13 + 1401
240偶數，除以 2202
320偶數，除以 2103
410偶數，除以 254

此時 start = 5，不再符合 start > 6，所以離開迴圈。得到 (a) 4、(b) 5。

第二塊：函式參數決定 (c)、(d)

int x 是傳值

aValue 的值 0 被複製給 x。函式內把 x 改成 10，不會改到外面的 aValue，所以 (c) 是 0。

int v[] 可操作原陣列

陣列參數在函式中等同指標。*(v + 2) 就是 v[2]，因此外面的 values[2] 變成 100，(d) 是 100。

函式有 return x;，但呼叫時只寫 f(aValue, values);，沒有把回傳值指定給任何變數。因此回傳的 10 被丟掉。

第三塊：變數遮蔽決定 (e)

函式內的 int g = 123; 是區域變數，只在 f 裡有效，而且會暫時遮蔽同名全域變數。它不會改到外面的 g = 18。回到 main 後，cout << g 讀到的是全域變數，因此 (e) 是 18。

標記輸出直接原因
(a)4while 共執行 4 圈
(b)5start 變成 5 後停止
(c)0x 是傳值，aValue 沒被改
(d)100陣列參數讓函式改到 values[2]
(e)18函式內的 g 不會改到全域 g
